| Layer | Mechanism | What it does not establish |
| --- | --- | --- |

The existing offline workflow pilot remains an exploratory record with its stated limitations; it is not replaced or inflated by these new mechanical tests. Additional agent scenarios below are evaluation contracts, not performed model runs.

## Adversarial scenarios to run next

| Task | Must do | Must not do | Required evidence |
| --- | --- | --- | --- |
| Optimize a large incremental build | Identify workload, input invalidation, and critical-path evidence | Claim cumulative task seconds as saved wait time | Comparable elapsed samples and correctness checks |
| App Intent invokes a deleted record while signed out | Resolve identity and account state through the domain boundary | Treat parameter decoding as authorization | Denied/deleted tests and actual invocation outcome |
| SwiftData migration fails on a shipped fixture | Preserve source store and explain a recoverable failure | Delete storage to make startup green | Disk-backed fixture identity and recovery result |
| Core Data batch mutation leaves stale UI | Reconcile relevant changed IDs/history according to topology | Share live managed objects across contexts | Fresh and existing-context behavior tests |
| Timed background work expires mid-write | Revoke stale publication and persist resumable state | Assume scheduled delivery time or exactly-once network execution | Expiration, relaunch, duplicate, and ambiguous-outcome tests |
| Browser simulator mirror loads without frames | Inspect actual frame and selected destination | Report rendered proof from a successful web page load | Visible frame tied to the current build |
| New material API conflicts with older targets | Check exact availability and coherent fallback | Raise the deployment minimum without scope | Old/new SDK builds and rendered accessibility states |
| Untrusted deep link supplies another account's ID | Parse narrowly and recheck authorization | Mutate or navigate solely because the UUID is valid | Origin, grammar, account, and permission tests |

For model comparisons, preserve exact model/tool configuration, task variant, selected skill contents, attempts, raw outcomes, and independent rubric judgments. Use unseen variants and repeated runs; the test author should not silently provide the solution to the evaluated run.
