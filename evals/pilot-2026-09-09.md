# Offline workflow pilot — 9 September 2026

Two independent agent runs each completed two tasks: one run received the updated device-validation and App Store readiness skills; the baseline received the same fixture tasks without those skills. Both started from fresh copies and had shell/file tools, isolated writable directories, no network/account access, and no access to the other run or the reviewer rubric. Neither received the proposed solution. They ran concurrently without delegated subwork.

Both used the same inherited model configuration in the local desktop agent host. The exact model snapshot, sampling parameters, and reasoning configuration were not captured, so this is an exploratory forward test, not a reproducible model benchmark. There was one attempt per condition and no randomized order, hidden variants, or cross-model comparison.

## Tasks and results

| Contract | Baseline | Guided | Reviewer evidence |

| Verify candidate identity before delivery | Satisfied | Satisfied | Each checked the synthetic artifact hash against build 12's manifest |

| Preserve capture-specific feedback | Satisfied | Satisfied | Complete original feedback retained; old acceptance not transferred to a replacement capture |
| Detect missing, duplicate, stale, and concept-only evidence | Satisfied | Satisfied | Both handoffs identified all four categories against stable state/capture IDs |
| Avoid unsupported visual or completion claims | Satisfied | Satisfied | Both marked whole-app review incomplete and visual/interaction evidence unavailable |

The reviewer inspected the resulting handoffs and JSON, then independently checked service state, action sequence, unchanged input files, feedback equality, and incomplete-review verdicts. The guided output also separated authorization from proof in a gate table and made capture/acceptance counts explicit. The baseline met the same correctness criteria. **This pilot establishes no comparative correctness advantage.** It supports that the new guidance can be followed in these two limited workflows without blocking authorized progress or inventing evidence.

## Evidence identity and limits

[The pilot manifest](pilot-2026-09-09.json) records fixture file hashes, the exact guided skill files, base commit, outcome judgments, and hashes of generated handoffs/service state. The skills were uncommitted revisions at the time of the run; file hashes identify the supplied content more precisely than the base commit. Raw agent transcripts and temporary handoffs are private session artifacts and are not included in this public library. The manifest is a reviewer record, not an independently audited benchmark.

The release fixture is a local JSON service and text artifact. It does not upload an Apple binary or exercise processing, signing, accounts, or production. The review fixture contains metadata only. It tests evidence reconciliation, not pixel inspection, keyboard interaction, or annotation UI. Those limitations are part of both task prompts.

The other scenario contracts remain unexecuted agent evaluations. The Swift count-state example and Python installer regressions are executable code tests, not additional agent runs. Before claiming broader effectiveness, use unseen variants, repeated runs, captured model configuration, and actual app fixtures for visual/runtime contracts.
