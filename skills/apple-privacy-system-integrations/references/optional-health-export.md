# Save a workout when Health sharing is unavailable

The user ends a session in a training diary. Store its actual start, finish and app-specific interval history in the diary. If they elected Health export, map only facts the app can support. An unmeasured energy quantity stays absent. A session saved locally can show “Saved” while its Health export is still pending.

Before the system prompt, explain which feature will read or write which data. Inspect the requesting target’s signed capability and built usage descriptions. Inspect the archive’s privacy report for included SDKs and PrivacyInfo.xcprivacy declarations. Match applicable declarations to the API or data use and compare off-device transfers to the App Store privacy answers. Keep the current policy reachable from Settings. A policy link near Continue is a disclosure, not a grant of access.

For reads, an empty HealthKit query can mean there are no accessible samples. Offer the local task and a neutral explanation. For writes, record the actual result. If a write or acknowledgement is interrupted, reconcile the original export by its supported identity before retrying. Check both stores after a retry. Decide separately what removing the diary entry does to a previously exported record, and tell the person what the app can remove.

If the same diary also indexes sessions in Spotlight or shows them on the Lock Screen, decide which details belong on each surface. Sign out and search for a previously indexed private title. Clearing local navigation state alone can leave a system-owned copy discoverable.
