# Save a workout when Health sharing is unavailable

Store the session and interval history in the training diary. If the person enabled Health export, record its outcome separately. A local “Saved” and a pending export can both be true. Leave unmeasured energy absent.

**Separate reading from writing.** HealthKit’s authorization status for a type concerns permission to save that type. It cannot establish read access. An empty successful query calls for “No readings available.” A failed query deserves its actual recovery path. Use the export’s write result to decide whether to mark it delivered.

Before requesting access, explain the feature that needs it. Check the relevant usage description in the built target and the capability in its signature. When reviewing store privacy answers, trace actual SDK and off-device data flows alongside the archive’s privacy report. Keep the policy reachable after onboarding.

Interrupt an export after it was accepted. Reconcile the original record before retrying and check for one exported workout. If the diary also indexes sessions in Spotlight, sign out and search for a previously indexed private title. Verify that old results cannot open or disclose it. Make clear whether deleting the diary entry also removes an exported Health record.
